## A second correction to README.md

The Companion section told a reader both download options "download the official signed APK through the
console's own domain." A self-host publishes no APK, and the route that would serve one is not served
until the deployment names where its build lives — so the sentence promised a file that returns nothing.

Now it says what is true: the console serves the app from the deployment's own domain, a self-host builds
it and points two settings at where it put it, and until then the route is not served at all. The
alternative — a link to somebody else's build of a financial app — is the outcome the original wording
implied and the one nobody should ship.

**APPROVED.** Same basis as above: a statement a reader could act on and be wrong about, checked against
the reverse-proxy configuration that decides it.

## One further string: the crawl key's expiry rule

> a key that can start a crawl must expire

Returned with HTTP 400 on the field, when an owner mints a key carrying the crawl scope without an
expiry. Read by whoever is setting up their own automation, in a validation response beside the field.

- **It states the rule, not a fault.** The reader has not done anything wrong; they have asked for
  something the product will not issue in that shape.
- **It says which key and which requirement,** so a reader minting several keys knows which one is being
  refused and what to add. "expiresInDays is required" would be true and would not explain why only this
  key needs it.
- **"start a crawl" is the product's own phrase** for the thing the scope permits — the console button
  says the same — rather than a synonym invented for an error message.
- **It does not lecture.** The reasoning belongs beside the scope in the code and in the guide; a
  validation message that argued its case would be read once and resented.

**APPROVED.** No changes requested.
